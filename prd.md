Product Requirements Document (PRD)Nama Proyek: POS Sakopi SarojaPlatform: Aplikasi Android (Fokus Tablet & Smartphone)Teknologi: Flutter (Frontend), Supabase (Backend, Database, Auth)Arsitektur: Feature-First dengan Repository Pattern & Riverpod (State Management)1. Ringkasan ProdukPOS Sakopi Saroja adalah aplikasi Point of Sale khusus untuk operasional kedai kopi. Aplikasi ini mengintegrasikan pencatatan pesanan kasir, manajemen inventori/menu oleh admin, dan pemantauan performa keuangan oleh pemilik kedai (owner) dalam satu platform terpadu berbasis cloud.2. Aktor & Akses Pengguna (Role-Based Access)Aplikasi memiliki sistem autentikasi tunggal (Login) yang akan mengarahkan pengguna ke dashboard yang berbeda sesuai dengan perannya.2.1. Kasir (Cashier)Fokus pada transaksi langsung dengan pelanggan dan manajemen antrean pesanan.Halaman Kasir (POS):Menampilkan grid menu dengan filter kategori (Semua Menu, Kopi, Non-Kopi, Snack).Menampilkan detail produk (Gambar, Nama, Harga).Sistem Keranjang (Cart): Menambah pesanan, mengatur jumlah (+/-).Ringkasan Biaya: Subtotal, Pajak, dan Total.Opsi Pembayaran: Tunai dan Non-Tunai (Integrasi Midtrans/QRIS).Tombol "Bayar Sekarang" untuk memproses transaksi.Halaman Antrean (Queue):Melihat daftar pesanan aktif hari ini.Menampilkan detail tiap antrean: Nomor Pesanan, Waktu, Metode Pembayaran, Total Harga, dan Detail Item.Tombol "Selesaikan" untuk mengubah status pesanan dari "Diproses" menjadi "Selesai".2.2. Admin (Store Manager)Fokus pada manajemen operasional, ketersediaan produk, dan pemantauan kasir.Halaman Ringkasan (Dashboard):Metrik Utama: Total Menu Aktif, Menu Habis, dan Jumlah Transaksi Hari Ini.Pintasan cepat (Quick links) untuk menambah menu atau memantau transaksi.Halaman Manajemen Menu:Melihat daftar seluruh menu kedai.Aksi: Tambah Menu Baru, Edit Menu, Hapus Menu.Toggle Status Ketersediaan: Mengubah status produk antara "Tersedia" dan "Habis" (Otomatis menghilangkan produk dari layar Kasir jika habis).Halaman Riwayat Transaksi:Memantau 100 transaksi terakhir yang diinput oleh kasir.Menampilkan status transaksi (Selesai/Diproses), nama kasir, metode pembayaran, dan total.Fitur melihat/mencetak ulang struk (ikon dokumen).2.3. Owner (Pemilik Kedai)Fokus pada analisis keuangan, laba/rugi, dan manajemen staf.Halaman Laporan (Reports):Metrik Keuangan Bulanan: Pendapatan Kotor, Beban Pengeluaran, Laba Bersih (Net Profit).Visualisasi Data: Grafik Donut Proporsi Pembayaran (Tunai vs Midtrans) dan Grafik Batang Top 5 Menu Terlaris.Aksi: "Unduh PDF" laporan dan "Reset Transaksi" (Opsional/Berbahaya).Halaman Pengeluaran (Expenses):Formulir untuk mencatat pengeluaran operasional toko bulanan (Beban Operasional).Daftar riwayat pengeluaran untuk memotong Pendapatan Kotor menjadi Laba Bersih.Halaman Manajemen Akun (Staff Accounts):Menambah akun baru untuk pegawai.Menentukan Role (KASIR, ADMIN, OWNER).Aksi Edit/Hapus akses pegawai.3. Desain Arsitektur: Repository PatternProyek ini akan menggunakan Repository Pattern untuk memisahkan logika antarmuka (UI/Flutter) dari logika komunikasi data (Supabase). Ini membuat kode lebih clean, mudah di-test, dan mudah dirawat.3.1. Struktur Folder (Feature-First)lib/
├── core/                       # Pengaturan Global
│   ├── config/                 # supabase_config.dart
│   ├── theme/                  # app_colors.dart, app_theme.dart
│   └── routing/                # app_router.dart (GoRouter)
├── features/                   # Modul Berdasarkan Fitur
│   ├── auth/                   # Fitur Login & Sesi
│   ├── cashier/                # Fitur Halaman Kasir
│   ├── admin/                  # Fitur Manajemen Menu & Riwayat
│   └── owner/                  # Fitur Laporan & Akun
└── main.dart                   # Entry Point
3.2. Lapisan Repository (Setiap Feature)Setiap folder feature akan dibagi menjadi tiga lapisan:Domain (Models & Interface): Mendefinisikan bentuk data (Class) dan kontrak fungsi (Abstract Class). UI hanya boleh tahu lapisan ini.Data (Implementation): Implementasi pemanggilan API ke Supabase.Presentation (UI & State): Widget Flutter dan Provider (Riverpod) yang menghubungkan UI dengan Domain.Contoh Implementasi: Manajemen Menu (Admin)domain/menu_model.dart (Bentuk objek Menu)domain/menu_repository.dart (Abstract class: getMenus(), addMenu())data/supabase_menu_repository.dart (Eksekusi query Supabase.instance.client.from('products')...)presentation/menu_screen.dart (UI yang memanggil ref.read(menuRepository))4. Rancangan Database (Supabase Schema)Berikut adalah rancangan awal tabel PostgreSQL di Supabase yang dibutuhkan untuk mengakomodasi seluruh fitur di atas:users_profile (Relasi dengan Supabase Auth)id (UUID, PK)email (String)role (Enum: 'kasir', 'admin', 'owner')name (String)categoriesid (Int, PK)name (String) - Contoh: Kopi, Non-Kopi, Snackproductsid (Int, PK)category_id (Int, FK to categories)name (String)price (Numeric)image_url (String) - URL dari Supabase Storageis_available (Boolean) - Default: truetransactionsid (String/UUID, PK) - Contoh: #ORD-260719-5325cashier_id (UUID, FK to users_profile)total_amount (Numeric)payment_method (Enum: 'Tunai', 'Midtrans')status (Enum: 'Diproses', 'Selesai')created_at (Timestamp)transaction_itemsid (Int, PK)transaction_id (UUID, FK to transactions)product_id (Int, FK to products)quantity (Int)price_at_time (Numeric) - Mencegah perubahan harga produk merusak data masa laluexpenses (Untuk fitur Owner)id (Int, PK)amount (Numeric)description (String)expense_date (Timestamp)
